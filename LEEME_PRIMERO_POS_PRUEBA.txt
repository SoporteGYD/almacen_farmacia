DISTRIBUCIÓN G&D | PUNTO DE VENTA CON REGISTRO REAL EN BD DE PRUEBAS
=============================================================

OBJETIVO
- Proyecto local: C:\xampp\htdocs\almacen-farmacia2
- Base de datos local: prueba (MySQL host 127.0.0.1; puerto 3307; usuario root)
- No modificar la carpeta original almacen-farmacia ni Ubuntu.
- Esta entrega parte del ÚLTIMO ZIP completo del proyecto compartido en este chat.
  Si tu carpeta almacen-farmacia2 tiene cambios posteriores, prefiere el ZIP
  SOLO_CAMBIOS... y haz primero copia de la carpeta; no reemplaces todo a ciegas.
- No se incluye una copia de tu SQL ni de datos reales en estos archivos.

INSTALACIÓN EN XAMPP (LOCAL)
1. Haz respaldo (EXPORTAR SQL) de la base prueba en phpMyAdmin, y copia
   toda la carpeta C:\xampp\htdocs\almacen-farmacia2 a otra ubicación.
2. Descomprime el ZIP SOLO_CAMBIOS sobre la carpeta almacen-farmacia2
   conservando los directorios app, public, sql y scripts.
3. Abre app/config/database.php y confirma:
     host = 127.0.0.1 ; port = 3307 ; dbName = prueba
   ESTE ES EL ÚNICO CAMBIO DE BD. No apuntar a Ubuntu.
4. En phpMyAdmin del servidor 127.0.0.1:3307, importa el archivo:
     sql/pos_instalacion_prueba.sql
   El SQL usa explícitamente USE `prueba`; agrega las tablas pos_ y el rol CAJERO.
   NUNCA LO EJECUTES EN LA BD DE PRODUCCIÓN.
5. Crea la cuenta de prueba desde Git Bash/PowerShell ubicado en carpeta2:
     C:\xampp\php\php.exe scripts\crear_cajero_prueba.php
   Si estás en Git Bash:
     /c/xampp/php/php.exe scripts/crear_cajero_prueba.php
   Anota la contraseña que se muestra una sola vez.
   Usuario: cajero_prueba; almacén asignado: CD Hidalgo.
   También puedes dar de alta un usuario CAJERO desde el módulo Usuarios,
   asignándole el almacén CD HIDALGO o TUXTLA GUITIERREZ.
6. Entra como ADMINISTRADOR al módulo de pruebas:
     http://localhost/almacen-farmacia2/public/pos_configurar.php
   Busca por descripción/código y carga un PRECIO PÚBLICO y EXISTENCIA POS
   para los productos que usarás en la prueba. NO se usan costos.
7. Abre http://localhost/almacen-farmacia2/public/pos.php
   Abre turno (ej. fondo $500), busca producto y agrega cantidades.
   Registra efectivo/tarjeta/transferencia o combina los importes.
   Para tarjeta/transferencia escribe una referencia y marca la confirmación.
   El sistema NO cobra automáticamente en terminal bancaria.
8. Al registrar la venta se crea folio PV-, detalle y pagos en tabla pos_ventas
   y se descuentan cantidades SOLO de pos_existencias_farmacia.
   El ticket se abre en una pestaña, desde donde presionas IMPRIMIR.
   En Chrome selecciona la impresora de tickets, papel 80 mm, escala 100%,
   márgenes Ninguno, encabezados/pies desactivados. Si corta a la izquierda,
   ajusta el margen del ticket de 9 a 11/13 mm (o a 7 mm si sobra espacio).
9. Inicia sesión con cajero_prueba: se redirige directamente a pos.php.
   Ese rol tiene bloqueo de acceso a los módulos protegidos del almacén.
10. Realiza cierre de turno y verifica los folios en la tabla pos_ventas.

TABLAS CREADAS
pos_sucursales, pos_cajas, pos_precios, pos_precios_historial,
pos_turnos, pos_ventas, pos_venta_detalle, pos_pagos,
pos_movimientos_caja, pos_existencias_farmacia, pos_auditoria.

CAMBIOS IMPORTANTES
- app/config/database.php se conecta exclusivamente a prueba.
- app/helpers/auth.php utiliza una cookie/sesión diferente a almacen-farmacia,
  para evitar colisiones con el sistema original.
- public/usuario.php y UsuarioController.php permiten el rol CAJERO.
- El POS valida el rol y las cajas por sucursal. Los CAJEROS solo pueden usar
  un almacén asignado (CD Hidalgo 1 o Tuxtla 3); admin puede probar todas.
- El POS registra VENTAS DE PRUEBA persistentes y descuenta stock POS de prueba.
- NO se afecta la tabla producto_existencias, los movimientos del almacén,
  WinCaja, ni datos del servidor Ubuntu.
- No se hacen cancelaciones/devoluciones todavía. No es facturación CFDI.
- NO SUBAS ESTOS CAMBIOS A PRODUCCIÓN durante las pruebas.
- El catálogo original y el inventario de almacén se conservan.

IMPORTANTE SOBRE PAGOS
Los cobros de tarjeta y transferencia son REGISTROS MANUALES confirmados
por el cajero. La app NO se conecta a un banco ni valida depósitos.
Cada vez que presionas 'Registrar venta' queda una venta de prueba en MySQL.
No se procesan cobros bancarios reales desde la app.

VALIDACIÓN
Se verificó sintaxis PHP y se revisó la lógica de transacciones y permisos.
Sin acceso a tu XAMPP no se pudo ejecutar la base MySQL ni la impresora física.
Prueba inicialmente 1-2 productos y revisa cada tabla en phpMyAdmin.
